# MindForge 当前项目上下文

> 沉淀时间：2026-08-31  
> 用途：记录本轮完整重构形成的产品判断、架构边界和交互共识，供后续设计与开发直接续接。

## 1. 项目定位

MindForge 是面向 Vue 3 的精品通用能力实验室，不以组件数量为目标。

只有同时满足以下条件的能力才值得保留：

1. 解决真实、常见且容易实现不完整的问题；
2. 相比普通封装覆盖明显更多的边界；
3. API 足够直观，可以跨项目复用；
4. 源码、类型、测试、Demo 和文档形成完整交付；
5. 有明确成熟度和长期维护价值。

普通 UI、简单工具函数、薄 Hook、无消费者的基础设施和纯技术抽象不进入仓库。重构时不保留 experiments、legacy 或 compatibility 目录作为低价值代码的避难所。

## 2. 当前架构

```text
packages/           可发布的正式能力
internal/           正式能力共享但不公开的实现
apps/playground/    真实交互演示与能力导航
apps/docs/          面向使用者的能力文档
.project/           产品边界、协作规范和阶段决策
```

- `packages/catalog.ts` 是正式能力的单一事实来源；
- `mind-forge` 是完整入口，子路径按业务能力导出；
- `internal` 永不公开，避免使用者依赖实现细节；
- 目录按业务问题组织，不按 components、hooks、utils 机械堆放。

## 3. 当前正式能力

### 3.0 Prompt Suggestions · Beta

- 面向 AI 对话、搜索和命令入口提供分组建议、说明、禁用态与业务 payload；
- 支持同步列表和异步 `source(context, signal)`，上下文变化、关闭和卸载都会取消旧请求；
- 即使数据源忽略取消，也通过请求序号阻止迟到结果覆盖新上下文；
- 键盘方向键会跳过禁用项并循环移动，支持 Home、End、ESC 和焦点恢复；
- 组件只发出选择事件，不绑定聊天 Store，也不决定填入、提交、导航或业务动作；
- 使用 Floating UI 处理翻转、位移和视口安全边距，并遵循减弱动画偏好。

### 3.1 Feedback Suite · Beta

由 Modal、Loading、Message 共享内部 Overlay Manager，统一处理层级和页面副作用。

#### Overlay Manager

- 所有浮层使用统一递增层级；
- ESC 只作用于最顶层可处理浮层；
- 不响应 ESC 的顶层 Modal 会阻止事件穿透到下层；
- body 滚动锁使用引用计数，最后一层关闭后才恢复原状态；
- 焦点陷阱忽略隐藏、禁用和 inert 节点，并阻止焦点逃逸。

#### Modal

- `closable` 只控制关闭按钮，不与 ESC、遮罩关闭绑定；
- 支持嵌套 Modal、顶层 ESC、遮罩关闭、焦点捕获与焦点恢复；
- 退场时先退出交互栈，动画结束后再释放页面资源；
- 移动端宽度受视口约束；
- 遵循 `prefers-reduced-motion`。

#### Loading

- 支持全局或局部容器、延迟展示、最短展示时间和原位更新；
- 局部实例会维护目标定位上下文、滚动状态和 `aria-busy`；
- 多实例通过引用计数恢复目标原始状态；
- 控制按钮应位于遮罩目标之外，避免被 Loading 自身阻挡。

#### Message

- Info、Success、Warning、Error 使用统一白色表面；
- 状态色只用于侧边细线、圆形图标和交互反馈；
- 默认宽度 `380px`，移动端保留 16px 安全边距；
- 支持主文案、辅助说明、进行中图标、容量限制和主动关闭；
- Promise 在同一位置从 pending 原位更新为 success 或 error；
- 悬停和键盘焦点都会暂停剩余倒计时，两种交互都离开后才恢复；
- Error 使用 `alert`，其余状态使用 `status`；
- 最后一条通知退出队列后，宿主继续保留原层级直到退场完成，避免被固定 Header 遮挡。

### 3.2 Typewriter · Beta

- 以状态机管理开始、暂停、恢复、跳过、重播、停止和清空；
- 按 Unicode 字素簇输出，Emoji、肤色修饰符和组合字符不会被拆开；
- 支持文本队列、独立停留时间、动态内容和完整事件；
- 内容变化时安全衔接当前状态；
- 减弱动画模式下直接呈现完整内容。

### 3.3 v-tooltip · Beta

- 基于 `@floating-ui/dom` 处理定位、偏移、翻转、位移和箭头；
- 支持 hover 与 focus 两条触发路径；
- 非交互元素需要 `tabindex="0"` 才能通过键盘聚焦，悬停不受此限制；
- ESC 关闭键盘焦点触发的提示；纯 hover 状态由指针离开关闭；
- 支持仅溢出时展示、延迟显隐、动态更新和完整清理；
- 提供深色、浅色和自定义主题变量；
- 箭头经过视觉修正，避免暴露旋转正方形的生硬边角。

## 4. Playground 与信息架构

- 导航固定为两层：一级是能力分类，二级是正式能力；
- 一级菜单采用手风琴交互，一次只展开一个分类；
- 一级强调分类与数量，二级保持轻量，不再套独立白色卡片；
- 二级使用能力图标替代普通圆点，不显示无实际作用的右侧箭头；
- 选中态由浅色背景、左侧状态条和文字颜色共同表达；
- 侧边栏在窄屏切换为抽屉，视口恢复后不能遗留错误隐藏状态；
- Header、搜索、面包屑、能力摘要和成熟度共同构成统一页面骨架；
- 首页文案只描述当前真实能力，不使用“组件丰富”等与精品定位冲突的泛化表达；
- 网站图标、标题和 GitHub 地址统一指向 MindForge 当前项目。

## 5. 设计协作共识

- 提出布局或视觉方案时，默认同时提供可视化 Demo，便于评估真实比例和层级；
- 先解决信息架构，再处理颜色、阴影和装饰；
- 视觉层级通过字号、间距、背景和密度共同建立，不依赖多层卡片嵌套；
- 状态色用于识别和反馈，不大面积侵占内容区域；
- 动效必须解释状态变化，不能妨碍关闭、聚焦或内容读取；
- 所有交互同时考虑鼠标、键盘、移动端和减弱动画偏好。
- 默认视觉语言使用低饱和靛蓝、冷灰中性色、7–16px 分级圆角和克制柔阴影；状态色只承担识别与反馈。
- 能力 Demo 共用表面、标题、按钮和说明条规范；公共组件通过带 fallback 的 CSS 变量保持可独立消费。

## 6. 工程与注释规范

- 每次代码变更必须同步检查文档、Demo、类型、测试和导出；
- 公共 API 使用 TSDoc，说明用途、默认值、单位或安全边界；
- 状态协调、竞态、资源清理和反直觉实现必须解释“为什么”；
- 注释通俗、一语中的，不能只复述代码；
- 模块顶层不直接访问浏览器全局对象；
- 定时器、监听器、Observer 和共享副作用必须完整清理；
- 交付门禁固定为测试、库构建、Playground 构建和文档构建。

## 7. 已删除内容与重新引入条件

通用 Mock 服务已经删除，包括 CRUD、认证、短信、OSS、SSE、静态资源、代理和专属依赖。

原因不是 Mock 技术无价值，而是这些接口没有被当前正式能力消费。未来只有上传、流式响应、取消、重试、竞态或断线恢复等正式能力确实需要网络边界时才重新引入；默认使用能力就近 fixture，独立服务必须有类型检查、测试和文档。

## 9. 后续工作原则

下一项能力不能从“还能封装什么”出发，而应先回答：

1. 具体解决哪个高频业务问题？
2. 普通实现最容易遗漏哪些边界？
3. 与成熟生态相比，MindForge 的差异价值是什么？
4. 能否用一页 Demo 直观证明价值？
5. 是否愿意长期维护其类型、测试、文档和兼容性？

答案不充分时，不进入正式能力目录。
